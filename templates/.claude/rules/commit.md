# 커밋 규약

## 접두어 (필수)

| 타입 | 언제 사용 |
|------|-----------|
| `feat:` | 새 기능 추가 |
| `fix:` | 버그 수정 |
| `refactor:` | 동작 변경 없는 코드 개선 |
| `docs:` | 문서만 변경 |
| `chore:` | 빌드·의존성·설정 변경 |
| `test:` | 테스트 추가·수정 |

## 제목 규칙

- 한국어로 작성, 50자 이내 권장
- 명령형 현재 시제: "추가한다" 아닌 "추가"
- 마침표 없음
- 올바른 예: `feat: 로그인 에러 메시지 한국어 번역`
- 잘못된 예: `feat: 로그인 에러 메시지 한국어 번역을 추가했습니다.`

## Issue 연결 규칙

- `feat:` / `fix:` 커밋은 반드시 Issue 번호 포함: `feat: 결제 모듈 연동 (#42)`
- Issue 없이 feat/fix 커밋 금지 — PR 파이프라인이 자동으로 block함
- `refactor:` / `docs:` / `chore:` / `test:`는 Issue 없이 main 직접 커밋 허용

## 브랜치 규약

- feat/fix 작업: `feature/#N-짧은-설명` 브랜치 → PR 경유 머지
- 예: `feature/#42-payment-integration`

## 원자적 커밋

- 커밋 하나 = 변경 이유 하나
- 리뷰어가 한 커밋만 보고도 의도를 파악할 수 있어야 함
- "그 김에" 수정은 별도 커밋으로 분리

## 커밋 전 체크리스트

- [ ] `.env` / 인증서 / 시크릿이 스테이징 영역에 없는지 `git status`로 확인
- [ ] 의도하지 않은 파일이 포함되지 않았는지 확인
- [ ] 빌드·린트 통과 확인
